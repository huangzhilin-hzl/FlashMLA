# 当前实现与优化结论

目标固定为 B300 GPU1 上的 `b8192, s_q1, H64, Dqk576, Dv512, TopK2048`，
输入 Q/KV 为 E4M3 FP8，输出 BF16。原始测试脚本、参考计算和误差阈值保持不变。

目前默认快速版本是 **v190**。四轮同进程换序 Graph 测试的暖缓存为
1.610–1.612 ms，同轮 TRTLLM 为 1.867–1.870 ms。暖、冷缓存共八次比较
均快于前版 v183；收益主要来自冷缓存。独立 100 次 Graph 长测约
1.643/1.632 ms（暖/冷），不同执行方式的时延不能直接混比。

快速版本并非完整 FP32 参考检查零误差：两个全量种子分别有 9 和 6 个元素超出
原始容差，与 TRTLLM 的失败位置和数值相同；短序列和带空洞索引的误差更明显。
需要已审计输入完整容差通过时，当前高精度版本是 **v197**。两组全量种子、
全量短序列和带空洞输入均与 v184 逐位一致，保留了 v148 独立全量 FP32 检查
通过的结论。五轮换序暖缓存为 1.811–1.817 ms，冷缓存为 1.796–1.799 ms，
十次均快于前版 v191；同轮 TRTLLM 暖缓存为 1.868–1.887 ms。独立 Graph
暖/冷缓存为 1.812/1.836 ms，也快于同轮 TRTLLM 的 1.884/1.919 ms。
后续按独立进程换序复测，4.6.2 的暖缓存为 1.842–1.888 ms，其中两轮
略慢于同轮 TRTLLM。暖缓存优势仍依赖运行条件，不能只引用较快的一组数据。
后续关闭 NVML 采样的四轮对照为 1.874–1.886 ms，均略慢于同轮 TRTLLM；
冷缓存四轮仍更快。整段运行采样出现不同 SM 时钟和功耗限制状态，尚不能
把它换算成单次 kernel 的时钟或归因全部时延差异。
预热改为 500 次的补充对照中，关闭采样的 v197 暖缓存为 1.850–1.852 ms，
TRTLLM 为 1.925–1.933 ms，三轮均更快；该参数不同，单独保留。
轮转脚本前后的 nvidia-smi 查询会引入额外空闲：关闭后 v197 暖缓存约
1.85 ms，开启时约 1.81 ms；关闭查询的十二次暖/冷比较仍全部快于 v191。
此前轮转数据应注明含查询间隔，今后辅助轮转默认关闭这些查询。

v197 在 v184 上把 CTA 扩为四个完整 warpgroup，将搬运与提交角色设为
64 个寄存器、计算角色设为 176 个；初始 CTA 寄存器预算足够满足重分配。
寄存器申请必须放在实际计算分支里，提前申请再汇合的版本仍编译失败。
相比 32/192 的分配，v197 减少了约 4.7% 的动态指令；其中一部分是 UR/R
之间的额外搬运。两版 local-memory 流量都为零，不能把这类搬运称为显存溢出。

v190/v191 仅在 v183/v184 的输出写回加入 L2 evict-first。硬件采样显示
DRAM 读取量下降约 8.6%，但该组插桩时延没有改善；未插桩轮转测试中的
实际收益远小于流量降幅。访问和同步检查通过，NCU local-memory 流量为零。

v183/v184 使用 SM103 的 TMEM load/max，在位图全有效时通过实际机器分支
跳过掩码和软件 MAX；有空洞时保留完整回退计算。编译器会把普通条件分支改成
predication，最终使用边界明确的两目标索引分支才减少了实际发射指令。访问、
同步检查均通过，NCU 的 local-memory 流量为零。

v129/v133 分别在快速/高精度版本上把输出的 L2 淘汰优先级设为 evict-first。
v141 则把同样的输出策略叠加到 v138 上。三者都已通过两组全量种子、短序列和
空洞输入的逐位等价验证。收益较小且与执行
方式有关，因此先作为备选，不替换默认版本。v129 的一组硬件采样显示 DRAM
读取量减少约 8.8%；这不意味着端到端延迟也会同比下降。

v146 在 v138 上把位图读取提前到 QK 等待之前；SASS 确认了指令位置变化，
四轮暖/冷缓存均快于 v138，完整逐位验证也保持一致。

v152 叠加早读位图后，三轮暖缓存比 v148 快约 7–8 μs，冷缓存两胜一负。
完整逐位检查保留了 v148 的精度结论；后续 v153 改进同步，v160 再叠加 packed 缩放。
快速路径的 v150 合并生产者同步
后表现随测试顺序变化，v151 删除多余 fence 没有短测收益，均未替换默认版本。

查询 Q 的 evict-first 缓存提示提高了整体 L2 命中率，但没有降低时延。
B300 的 TMEM load/max 指令已通过访问与数值检查，但单独替换仍略慢。
掩码分支的组合版本产生额外 MMA 选举和控制指令而退步。位图提示、固定 issuer
线程及循环入口广播都未消除该开销。把完整 warp 的广播放进单线程选举区会违反
同步条件，相关候选已淘汰。按 warp ID 划分角色后，v177/v178 消除了额外 MMA
选举循环，恢复到 1.700/1.790 ms，但仍慢于默认版本。角色划分单独作用于默认
内核也没有收益。后续 v183/v184 保留实际分支后取得稳定的同轮收益。
简化角色条件后的 v185/v186 收益较小且有退步，暂留作完整验证的备选。
回退归约临时变量和原地缩放均未降低寄存器数；后续输出缓存策略形成 v190/v191。
隔离的 CuTeDSL 4.6.3 使旧失败例进入 PTX 汇编阶段，但仅升级仍未通过编译。
把寄存器申请移入计算角色分支后，原有 4.6.2 也能编译。v195/v197 通过访问、
同步、两组全量种子、短序列和空洞等价检查。v197 通过长测后成为高精度默认版。
v202 叠加输出缓存提示后，冷缓存有所改善，但暖缓存结果仍有退步，暂留作备选。
4.6.3 的独立进程输出字节与 4.6.2 全部一致，但四轮冷缓存均更慢，暂不升级。
v203/v204 的长度一致性提示产生相同机器码；v205/v206 去掉最终分母交接同步
后，换序性能仍有退步，均未替换默认版本。
关闭查询后的 v206 比较更有利，补充两组种子、短序列和独立长测已完成，
暂留作完整验证的备选。v207/v208 的相邻节点打包加法增加了搬运指令，
短测退步。v209/v210 的固定半树布局减少了部分搬运，也通过访问与等价
检查，但仍慢于默认版。单 CTA 诊断中的 packed 加法略快，未支持其依赖延迟
更差的猜测；该结果不能直接换算为 MLA 收益，当前完整归约的寄存器搬运仍有代价。

v211/v212 仅合并 TMA 汇编未减少参数复制，未进入运行测试。v213/v214
通过实际循环复用 TMA 坐标，访问与等价检查通过，但短测退步到
1.679/1.751 ms。动态计数确认 v214 的总指令反而增加约 5.9%，
地址更新、比较与分支抵消了坐标复制的节省，默认版保持不变。

v215/v216 改用打包 FP16 残差计算后，第一组全量种子和空洞输入通过
原阈值，但误差略升，短测 1.667/1.673 ms 也未改善 v197，均未推广。

近期 ExpCast-FP8 论文提供了省去指数与转换的思路，但本地概率路径诊断
在短序列和空洞输入上增加超差元素；原阈值不允许直接替换，暂不移植。

64/184 寄存器分配的 v217 减少了静态搬运，访问与等价检查通过，
但短测 1.666 ms 未改善默认版；56/184 的 v218 增加 UR/R 搬运，仅保留编译记录。

隔离的 CuTeDSL 4.7.1 对当前两版内核完成访问、同步和全部输入的输出哈希
对照，结果与 4.6.2 一致；两轮独立长测的暖缓存排序互有变化，高精度路径
冷缓存均稍慢，未升级默认编译器。

v219–v224 尝试用 16 字节 cp.async 替换稀疏 KV 的 TMA gather4。
显式修正共享内存 swizzle 地址后，访问与第一组全量逐位检查通过。
调整为八个线程覆盖 128 字节主通道后，额外 shared wavefront 明显减少，
但 v223/v224 短测为 1.558/1.674 ms，仍未改善默认版。当前 576 字节行步长
使奇数 KV 行的 128 字节访问错开 64 字节；这组输入的地址计数精确对应
源码采样中的额外 wavefront 数，但不能换算为等比例时延收益。
v225/v226 把拷贝完成通知合并为一次发布后，短测退步到 1.698/1.750 ms，
减少通知的代价是改变了流水线重叠，均未推广。

新的 normal-M64 双 datapath 布局已在 256 列 TMEM 下通过保存、覆盖、恢复
和累加的精确检查，包括 296 CTA 的内存与同步检查。完整 v227 尝试同时
容纳两个 CTA，并利用 warp 内归约减少同步。初次失败已定位为 LD.RED
半区偏移默认为 0，修正为 32 后访问和同步检查通过。第一组全量种子仍有
9 个超差元素，空洞输入为 66 个，不能称为原阈值全量通过。NCU 确认
寄存器与共享内存上限允许每 SM 两个 CTA，但短测 1.798 ms 慢于
同轮 TRTLLM 的 1.690 ms。共享内存源码采样的额外 wavefront 为零，
主要等待仍在 QK、PV 和 KV 缓冲复用；更高 tensor 活跃率没有带来时延改善。
v228 缩减普通 MMA 提交代码后短测仍为 1.798 ms。v229 复用已完成 QK 的
KV 尾部存放高精度概率残差，访问、同步、第一组全量种子和空洞精度均通过，
动态共享内存仍为 115,296 字节；但短测 1.897 ms 未改善现有高精度版。
普通 MMA 无法沿用原 `.ws` 路径的编号 B collector，也增加了重复读取成本。
这组实验尚未支持两 CTA 方案替换默认版。KV 尾部复用单独用于原流水线的
v230/v231 后，访问、同步和第一组全量逐位检查通过，但短测
1.670/1.565 ms 均未改善默认版本。v231 虽从 123 降至 111 个寄存器，
共享内存也减少 8 KiB，仍未突破原先的单 CTA 资源限制。

128 列 TMEM 输出保存、覆盖、恢复及分数最大值检查已通过，包含
单 CTA 和 296 CTA 的 memcheck/synccheck，各三次重复。这个诊断为
恢复 128-key tile、单 KV 缓冲的普通 MMA 候选提供依据。完整 v232 的
访问、同步检查通过，第一组全量精度仍有与 TRT 相同位置的 9 个超差元素，
空洞测试为 86 个。短测 1.942 ms 慢于同轮 TRT 的 1.692 ms；源码采样
中额外 shared wavefront 为零，KV 缓冲空／满等待较多，单缓冲方案未改善时延。

v233 尝试跨输出 datapath 半区复用普通 MMA 的 A collector。虽然小规模
带检查测试通过，不插桩的逐位对照却有约一半输出错误，全部位于第二半
输出，2 CTA 也能复现。独立整数矩阵诊断中，同一 datapath 半区复用
和不复用均在 1／296 CTA 下精确通过，跨半区复用则失败，且带检查运行
可能掩盖错误。该跨半区用法已排除，v233 未测速。

混合 `.ws` QK 与普通 MMA 输出的 TMEM 保存／恢复诊断已在
带检查与不插桩模式下通过 1／296 CTA 的精确验证。v234 将它用于
双 64-key KV 缓冲流水线，访问、同步及三次不插桩全量逐位对照通过，
精度与 v228 一致，仍有 9／66 个全量／空洞超差元素。短测 1.671 ms
改善了普通 MMA 对照的 1.798 ms，但仍慢于 v190 的 1.549 ms，未替换默认版。

v235 仅将加载循环展开两次，访问、同步、第一组全量种子、完整短序列和
空洞输入与 v190 的逐位对照均通过，继承原先的快速路径精度限制。短测
1.550 ms 与 v190 的 1.549 ms 基本相同，NCU 时长和 tensor 活跃率也接近。
高精度对应版 v236 因加载线程寄存器不足出现 128 字节栈；v237/v238 调整
分配后依次降到 64/8 字节，仍有实际 LDL/STL，均未运行。v239 进一步按
完整 warpgroup 区分加载和提交线程的预算，却因共同分支汇合仍出现 160 字节栈。
v240 将分配移入各自的工作分支后，栈和 LDL/STL 均为零。访问、同步、第一组
全量种子、完整短序列与空洞逐位对照均通过；短测 1.673 ms 仍慢于 v197
的 1.662 ms，未替换默认版。v241 的同组验证也通过，但短测仍为 1.673 ms，
未减少寄存器搬运。v242/v243 改由 PV 完成事件直接释放 KV 缓冲，同组验证
均通过，短测为 1.553/1.675 ms，尚未改善默认版。v244/v245 进一步测试
用下一次 QK 完成通知覆盖前一次 PV，但 v244 被 synccheck 明确报告 Missing wait：
保留的独立 PV 屏障仍在每轮推进，却无人等待中间阶段，违反屏障复用规则。
v244 未测速，v245 未运行；v246/v247 移除这个屏障，改等最后一次 KV 释放。
修正版通过访问、固定/变长同步、第一组全量种子、完整短序列和空洞检查，
与已验证的 v242/v243 逐位一致。短测为 1.548/1.671 ms，快速版基本持平，
高精度版仍慢于默认 v197，未替换默认版本。源码采样显示等待主要转移到
QK，动态指令比 v197 增加约 1.4%。v248/v249 把位图读取移到 QK 完成之后，
访问、固定/变长同步及逐位对照均通过，但短测 1.567/1.669 ms 未改善默认版。
v249 动态指令比 v247 少约 2.66%，等待却进一步集中到 QK。v250 转而测试
两个独立分数缓冲及就绪状态仲裁，访问、同步和逐位对照均通过，但短测
1.686 ms 慢于对照。源码计数确认约 46.9% 的后续 QK 提前提交，计算线程却
仍先等 PV 才开始下一块 softmax。v251 将这个等待移到下一块概率转换之后、
共享概率写入和输出修正之前，同组检查均通过，短测改善到 1.640 ms，但仍慢于
默认快速版。NCU 基准时钟的排序不同，不能据此推广。v252 继续测试单个选出线程
负责整段提交循环，同组验证通过，短测进一步改善到 1.626 ms，仍未超过默认版。
v253 在提前 QK 完成前 256 个通道后再次检查 PV 就绪状态，测试中途让出提交顺序
能否减少等待。同组检查通过，计数确认实际有 50,596 次中途先提交 PV，但短测
退步到 1.653 ms，未推广。v254 回到默认快速版，测试利用已有稀疏索引提前
预取 KV 到 L2。同组检查通过，但短测 1.624 ms 慢于默认版。配对缓存采样中
L2 请求增加约 55%、sector 数增加约 92%，DRAM 读取也略增；更高命中率没有
转化为收益。v255 保持原有数据搬运，只将下一轮索引读取提前到本轮 gather 前，
同组检查通过，短测 1.546 ms 与默认版接近，尚无确定收益。v256 将索引读取
移到第二个发布屏障之后，同组检查通过，短测 1.551 ms 仍未显示收益。
v257 转向高精度路径，测试双分数缓冲和延后 PV 等待；原有高位／残差概率
计算、collector 顺序和寄存器策略保持不变，正在编译与验证。

近期实验支持以下判断：

- 当前流水线需要优先提交已就绪的 PV。强制等待未来 KV 并提前 QK 的 v131
  退步到 2.038 ms；根据 KV 就绪状态选择提交顺序后，v132 回到 1.661 ms，
  合并通知的 v134 为 1.653 ms，但都未改善默认版本。
- 直接 256 位输出写回确实减少了共享内存中转。源码计数器对这种写指令报告的
  理论 sector 数不能按字面解释；硬件计数器确认输出流量仍是 512 MiB。
- 共享内存冲突的聚合计数不等于实际指令布局冲突。当前源码采样的实际与理想
  shared wavefront 数相同，excessive 为零，不能据聚合计数盲目改 swizzle。
- 默认 NCU 时钟控制曾逆转候选排序。性能排序使用未插桩配对测试；NCU 的基准
  时钟数据用于诊断，并另用解锁时钟采样确认等待位置。
- v135 的 256 列 TMEM 复用方案被 Tensor Core 访问检查拒绝，没有性能结果。
  保守分配 512 列的 v136 通过访问检查，但耗时 2.960 ms。静态元素映射和较高
  resident warp 数，都不能单独证明两个 CTA 正在并行做有效计算。
- 早期原生 x64 TMEM 加载与寄存器重分配组合有编译失败。后续 v198/v199
  在 4.6.2 上也能编译并通过访问与等价检查，但未取得性能收益。v138 改用两次 x32
  加载后合并等待，使用 123 个寄存器、零栈，NCU 确认零 local-memory 流量。
  迁移到高精度路径的 v140 和用于最终输出加载的 v142 均未取得短测收益。
  v138 的两组全量种子、短序列和空洞输入均与 v125 逐位一致，四轮暖/冷缓存换序均
  快于 v125。它减少了约 0.54% 的动态指令，实际时延收益也较小。
